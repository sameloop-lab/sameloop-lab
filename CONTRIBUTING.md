# Contributing

Discuss changes to the common contract before changing platform-specific behavior.
Keep native integration details in platform READMEs and link shared requirements.
Use English for project documentation and descriptive commits.

For a new implementation, include pinned prerequisites, build/run instructions,
API mapping, packaging, scenario outcomes and known limitations. Label untested
instructions and separate generated code from handwritten code. Document any
cross-stack bridge and its effect on observations.

For results, retain reproducible commands and raw evidence. Never claim production
use, platform support or successful tests without evidence. Original contributions
are submitted under this repository's MIT license; preserve third-party notices.

Before a documentation change is merged, check relative links, data-contract
consistency and the absence of credentials or machine-specific absolute paths.
Runtime checks will be introduced with the first runnable implementation.

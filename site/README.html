SameLoop Lab

Bind & Seek — Same Control Loop, Different Embedded Stacks.

GitHub organization · Repository · Français

SameLoop Lab is an open test bench for comparing embedded service architectures through one thermal-control application: a temperature sensor, a setpoint, a controller and a fan. We compare integration, communication, failure handling and delivery under explicit functional requirements. This is not a performance ranking.

Edition 0.2.0 — 25 October 2026. This repository contains documentation, signal catalogs, diagrams and imported validation evidence. Implementation packages are separate; their publication URLs and immutable revisions remain to be registered. A runnable component does not imply a complete platform integration.

The same functional contract

  • Observe temperature, quality, freshness and fan feedback.
  • Request OFF/AUTO and a finite setpoint between 15 and 40 °C.
  • Start OFF at 25 °C; keep requested and applied values distinct.
  • In AUTO, request clamp(20 × (temperature − setpoint), 0, 100) percent.
  • Treat invalid or stale measurements as unavailable; do not display missing data as zero.
  • Report overtemperature above 50 °C, independently of OFF/AUTO.

Read the functional specification. It describes the target contract; known deviations explain what the first implementations do not yet provide. The simulation's failure policy is not a safety design for physical cooling equipment.

Build the documentation

Node.js 20+ and Python 3 are required only to regenerate or check the documents.

npm ci
npm run build
npm run check

npm ci installs the locked dependencies, including markdown-it and @viz-js/viz (Graphviz in WebAssembly). Run it before the first build. The build itself works without network access. Edit Markdown, JSON and DOT sources; do not edit generated HTML, SVG or docs/projects.md by hand. See the documentation workflow.

Future testing extension

A proposed sameloop-tests would replay common failure scenarios against real services. Toxiproxy is a candidate for TCP disruptions and MockServer for selected service mocks. Neither is integrated in this release. See the scoped plan.
